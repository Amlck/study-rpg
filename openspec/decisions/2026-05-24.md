# Decisions — 2026-05-24

## 13:00 — GH Actions storage 警示 root cause = 二階題庫 PNG（治本要等 R2 archive 後另開 change）

5/23 早上的「You have used 100% of the Actions storage included」警示，當天做了**治標**處理：
- 砍 28 個舊 `github-pages` artifact（3836 MB → 288 MB）
- 兩個 deploy workflow 加 `cancel-in-progress: true`（避免連續 push 累積）

今天 audit `add-r2-cloud-sync-migration` task §9.1 才發現**真正的 root cause** 是別的：

> 「`apps/medexam2-hospital-tw/dist/images/medexam2-tw/` ships 396 question PNGs (X-ray / CT / MRI / pathology) totalling **77 MB**. Pages artifact rebuilds + retains **90 MB per deploy** → 5 deploys/day burst saturates the 500 MB free-tier quota.」

也就是說 144 MB pages artifact 裡 **77 MB 是 二階題庫的醫學影像 PNG**。即使加了 cancel-in-progress，每天 1–2 個成功 deploy 仍會 retain ~144 MB；連 4 天就到 0.5 GB cap。

**治本路徑**（R2 migration 自己標為 out-of-scope follow-up）：
1. 等 `add-r2-cloud-sync-migration` archive（estimated ~2026-06-12 Phase 4 + 14-day bake）
2. 開新 change `host-medexam2-images-on-r2`：
   - 把 396 PNG 移到 R2 public bucket（`study-rpg-images` 或類似名）
   - 加 build-time env var `VITE_IMAGES_BASE_URL`
   - 圖檔 reference 改成 `${VITE_IMAGES_BASE_URL}/images/medexam2-tw/<id>.png`
   - 二階 build 不再帶 images → artifact ~99 MB → ~23 MB（-77%）
   - R2 zero egress 永遠免費

**短期措施夠不夠（5–6 月）**：今天做的治標措施 + 6/1 quota reset = 撐得過 R2 archive 之前的 ~3 週。若中途又爆，可以提早開 `host-medexam2-images-on-r2`（不需要等 R2 migration archive，純粹是 OpenSpec 紀律建議照順序）。

**順帶提**：醫療影像 PNG 移走後可順手做 WebP 轉檔再省 -40%（共 -86% from baseline），但這是優化非必要。

**追蹤**：在 R2 migration archive 後立刻開 change，避免下次 storage 警示重新從零 diagnosis。對應 R2 migration 的 task §9.1 已記錄這條 follow-up（標 out-of-scope）。
