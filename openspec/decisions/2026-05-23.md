## 11:15 — GH Pages artifact storage 0.5 GB cap 警示 → 砍 + 防累積

GitHub 寄信「You have used 100% of the Actions storage included for the fireman333 account」（0.5 GB used / 0.5 GB included，6/1 reset）。

**根因**：5/22 一天 push 18 個 commit（DomainMigrationBanner / R2 CORS / leaderboardProfile fix / CF Pages workflow / tier labels 等），每 push 跑 `deploy.yml` 留下一個 143.9 MB `github-pages` artifact。累積到 30 個 / 3.84 GB，遠超 0.5 GB free quota。Free tier 的 storage 計費跟 Actions minutes 不同帳本 — public repo 雖然 minutes 不計，**artifact storage 仍計入 0.5 GB cap**。

**Actions minutes 不是問題**：5/22 為止 308 min / 2000 min（15%）、billed $0。警示 100% 純粹是 storage 那條。

**Immediate fix (done)**：
- `gh api repos/fireman333/study-rpg/actions/artifacts` paginate → 列出 30 個 artifact，按 `created_at` 排序保留最新 2 個、刪除其他 28 個
- 結果：3836 MB → 288 MB，釋放 ~3.55 GB；live site 不受影響（artifact 不是 serve source、deploy 完已消費）

**Follow-up（值得開 change 統一處理）**：
1. `.github/workflows/deploy.yml` + `deploy-cf-pages.yml` 加 `concurrency: { group: deploy-${{ github.ref }}, cancel-in-progress: true }`，連續 push 時 cancel 舊 run 不產 artifact
2. Audit 所有 `actions/upload-artifact` step，沒設 `retention-days` 的補上 `retention-days: 1`（`actions/upload-pages-artifact` 預設已 1 天，但其他 upload 可能漏）
3. bake-end 把 `deploy.yml` 翻成 redirect-only static HTML 後，此 workflow 不再 build → artifact 累積問題自然消失（見 [2026-05-23-bake-end-criteria.md](2026-05-23-bake-end-criteria.md)）

**長期策略**：retention 設好 + concurrency cancel + bake-end 退場三層防護，不會再單月爆 0.5 GB cap。

## 11:18 — openspec/config.yaml shape 修正

`openspec status --change <name>` 一直噴兩條 warn：`Invalid 'context' field in config (must be string)` + `Invalid 'rules' field in config (must be object)`。

**根因**：OpenSpec 1.3.0 (`/opt/homebrew/lib/node_modules/@fission-ai/openspec/dist/core/project-config.js:85-133`) 對 config schema 嚴格驗證：
- `context` 期待 `z.string()`（literal text < 50 KB），原本寫成 `{ project_md: openspec/project.md }` object 形 → reject
- `rules` 期待 `z.record(z.string(), z.array(z.string()))`（artifact_id → rule strings 的 object map），原本寫成 array of `{id, rule}` → reject

**修法**：
- `context` 整段移除 — `openspec/project.md` 已透過 CLAUDE.md `@openspec/project.md` import 自動進每個 session 的 prompt，OpenSpec 端重複注入沒收益
- `rules` 重組成 `{ proposal: [...], specs: [...], design: [...], tasks: [...] }` 物件，rule 文字依 artifact 語意分配（cross-cutting 規則跨多 artifact 重複 inline，總 ~3 KB 遠低於 50 KB 上限）
- 加 `schema: spec-driven` 顯式宣告
- 保留 `defaults:` 區段作 human reference（CLI 目前不消費此欄位但無害）

**驗證**：`openspec status --change add-hospital-equipment-medexam2` 不再有 warn；`openspec validate --all` 仍 52/52 pass。
